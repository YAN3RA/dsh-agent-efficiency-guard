feat(guard): make the three 思考限制 switches real and wire 总览 to live data

The Guard had one `duplicateDetection` master switch while the settings page
presented three independent ones, so two of those switches were cosmetic.
Split the capability and honour each switch in the detector:

- `alternatingCycleDetection`: off reports no cycle at all, leaving the
  repeat-reminder path untouched.
- `noProgressProtection`: off keeps detection and reminders but makes no call
  blockable, so the local denial never fires.

Switches persist in the plugin state file (version 3, with a `guard` section
and a v1/v2 read path), never the patch file: dsh watches patch files and
re-applies the plugin on every write, which would reload it on every toggle.
The Guard reads them through `ctx.capabilityPolicy.getGuard()` on each call,
so a toggle applies immediately without a reload.

Wired end to end: policy service getGuard/updateGuard -> Typert Remote ->
host-face METHODS -> client descriptors -> GuardContainer. 总览 now reads the
real Guard switches, the usage snapshot and the tier split from classifyAll,
so its numbers are no longer placeholders.

Failures are explicit: an unknown switch state renders disabled rather than
"off", and a rejected write restores the previous value and shows the reason.
